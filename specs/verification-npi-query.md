# Native RTL design queries

The local verification Agent and the native desktop expose one read-only Verdi NPI query tool. A user can find module instances by definition or hierarchical name pattern within an optional hierarchy, or select a hierarchical signal and ask for its drivers, loads, or both. Instances report their definitions and hierarchical paths. A signal result distinguishes driver and load endpoints, identifies the owning scope and the NPI object or statement, and includes available source-file and line evidence. Results distinguish no matching instance, missing or unsupported signals, empty direction, incomplete results, and EDA failures.

Every new RTL query requires the selected build's compiled KDB. The desktop accepts a VM file selection or typed path. Its native file picker can open shipped example databases from any workspace. MCP, CLI and Python accept the same `kdb` argument, relative to the workspace or absolute. With VCS O-2018.09 the `simv.kdb` file identifies the build and the sibling `kdb.elab++` directory holds the elaboration that Verdi opens. A containing `simv.daidir` or the elaboration directory itself is also accepted. The runner records both the selected path and the elaboration path. A missing input, unrelated file, or descriptor without its elaboration directory produces a KDB error before a job is queued. Verdi reports database load errors in the job evidence. RTL queries never elaborate a source filelist or select a default simulation profile. A completed query from an earlier version remains readable by ID with its original provenance.

```text
Desktop / Agent / CLI → native runner → Verdi batch / selected KDB → NPI evidence → result by job ID
```

SystemVerilog interface members resolve against the elaborated interface instance. The tool accepts concrete and bound formal member paths, including named modport views and simple modport renames. Declaration directions are displayed alongside actual readers and writers. Instance identity is retained across repeated modules, interface arrays and generate scopes. The acceptance design includes master and slave modports, unrestricted and forwarded ports, fixed bit selections, procedural and continuous uses, an if condition, and direct cross-hierarchy references. Tests verify source lines, direction, isolation of sibling buses and equivalent results for all three KDB entry points. Exercise the desktop file picker, MCP and Python with no HDL filelist or project profile in the query workspace. Run-time virtual interfaces and compound modport bit mappings require additional information.
