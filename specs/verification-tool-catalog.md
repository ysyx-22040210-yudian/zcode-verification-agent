# Verification tools in the local ZCode workspace

The Tool button in the VM desktop workspace opens a searchable catalog for the existing compiled-KDB RTL hierarchy and connectivity query, FSDB wave reader and VDB coverage extractor. Search accepts Chinese and English labels, artifact types, common engineering terms and exact MCP method names. A catalog entry opens its native view. A user can send a specific analysis or extension request to the workspace Agent using the selected tool. Ordinary chat can discover and use the same tools without opening the catalog.

```text
workspace Tool button / model tool discovery → native catalog and method schemas
desktop panel / Agent MCP / project Python extension → native runner → existing workspace job ID and evidence
```

The native runner owns metadata, schema references and project starter creation. The workspace shell owns navigation and uses its normal session admission path for an explicitly submitted prompt. Browsing and searching do not start a job or a chat. Selection, filters and drafts remain local UI state. Saved extension scripts use the same public Python client, method arguments, pagination and per-workspace receipts as MCP. Project scripts can combine all three tools. Template creation is idempotent and never replaces an edited file. Saved IDs remain readable. Every entry point requires a compiled KDB for new RTL queries.

Acceptance covers mouse and keyboard discovery, aliases, empty results, opening each native view, a normal chat dispatch and an explicit development request. Run the editable starters against real RTL, FSDB and VDB, modify a project script to answer a new requirement, and verify native job IDs and results against the existing read interfaces. Confirm tool registration and skill installation in a new and an existing local profile.
